## 0. Зачем это всё (5 мин · слайды 1–6)

- **[1]** Титул: «Репозиторий — центр мироздания проекта», лекция 1 из 2.
- **[2]** «Контакты»: три QR (GitHub, Telegram, NuGet) и почта текстом. Регалии голосом, на слайде их нет.
- **[3]** Вопрос в зал: «Кто собирается быть разработчиком ПО? А кто — вайбкодером?» Два голосования подряд. Вторых не осуждать: вопрос не в том, пользуешься ли ты ИИ, а в том, кто отвечает, когда он ошибся.
- **[4]** «Код подешевел»: что осталось дорогим против того, что стало дешёвым. Pull request сейчас ничего не стоит: агент откроет десять за час. Ценность переехала от написания к контролю — проверить, принять или отклонить, не сломать тех, кто уже пользуется, отвечать.
- **[5]** Фраза: «Профессионализм — это не размер кода, который вы способны написать, а размер хаоса, который вы способны контролировать». Проект из 50 разработчиков и агентов. Нужен механизм, который не зависит от доверия к конкретному человеку.
- **[6]** Пять навыков цепочкой: первые три — сегодня, последние два — в следующий раз.

## 1. Философия (15 мин · слайды 7–12)

- **[7]** Заголовок раздела и вопрос: «что должно лежать в репозитории, кроме кода?»
- **[8]** Диаграмма: репозиторий в центре; вокруг код, тесты, документация, задачи, решения, CI и правила, зависимости, релизы. Всё, что нужно знать о продукте, лежит в одном месте — или не существует.
- **[9]** «Проверка: человек с улицы»: пять вопросов новичка и где на них отвечает репозиторий. Self-contained: новый участник ничего не спрашивает, он клонирует и работает. Этот участник может быть агентом.
- **[10]** «Работа — это поставка артефактов»: «изучал», «нашёл проблему», «придумал», «обсудили», «почти готово» → документ, issue, черновой PR, комментарий, коммит. Вся работа — поставка цифровых артефактов. «Делал, думал, анализировал» без следа — имитация.
- **[11]** «Жалоба — это вклад»: «я не могу запустить проект» как issue против личного сообщения. Человек, который не смог запустить проект и оформил issue, сделал вклад: у нас плохие доки, ему говорят спасибо. Жаловаться нужно постоянно — в форме артефакта. Личное общение не оставляет следа.
- **[12]** Итог раздела: «Чего нет в репозитории — того не было».

## 2. Git в общих чертах (25 мин · слайды 13–23)

- **[13]** Заголовок раздела: команды выучите за вечер, сейчас — модель.
- **[14]** Диаграмма: три коммита цепочкой, стрелка «мой родитель», указатель main. Коммит — снимок всего проекта и ссылка на предыдущий. Имя коммита — хеш содержимого, поэтому прошлое нельзя изменить незаметно.
- **[15]** Диаграмма: рабочая папка → индекс → локальный репозиторий → удалённый; add, commit, push, pull. Индекс — то, что отличает Git от «сохранить всё»: в коммит идёт то, что выбрано осознанно.
- **[16]** Терминал: `git init`, `status`, `add`, `status`, `commit`. Проговорить построчно. В коммит попал один файл из двух.
- **[17]** «Один коммит — одна логическая мысль»: хорошие сообщения против плохих. Каждый коммит собирается, проходит тесты и объясняет себя сам. Формат «тип: что сделано» позже превратится в changelog и номер версии.
- **[18]** Терминал: `git switch -c`, `git log --oneline --graph --all` с развилкой. Ветка — указатель, она ничего не стоит. Пока вы работали, main ушёл вперёд.
- **[19]** Терминал: `git merge --no-ff` и граф после; справа три способа: merge commit, squash, rebase. Выбор способа слияния — выбор того, как будет читаться история.
- **[20]** Диаграмма: задача → ветка → коммиты → pull request → проверки и review → main, с возвратом «не прошло — исправить». В main никто не пишет напрямую. Pull request — просьба, её можно отклонить.
- **[21]** Таблица: девять команд на каждый день; `push --force` в общую ветку отмечен как запрет.
- **[22]** Терминал: `git bisect start`, `git bisect run`, найден первый плохой коммит. Двоичный поиск по истории: восемь коммитов — три шага, тысяча — десять. Работает только при атомарных коммитах.
- **[23]** «Чему в репозитории не место»: результаты сборки, секреты, большие бинарные файлы и Git LFS.

## 3. Организация репозитория (13 мин · слайды 24–28)

- **[24]** Заголовок раздела: что класть и где.
- **[25]** Дерево файлов репозитория слева, назначение каждого справа: README, CONTRIBUTING, CODEOWNERS, workflows, docs/adr, lock-файл, CHANGELOG, .devcontainer. Кода здесь две папки. Остальное делает из папки с кодом продукт, в который можно войти. ADR — запись «что решили, какие были варианты, почему».
- **[26]** «„Работает у меня“ — не аргумент»: lock-файл, версия SDK в репозитории, dev-контейнер, CI. Проверка: чистая машина, `git clone`, одна команда. Не собралось — ошибка репозитория, а не новичка.
- **[27]** «Зависимости — это чужой код в вашем продукте»: четыре правила и предупреждение о пакетах, выдуманных ИИ.
- **[28]** Итог раздела: «После merge у кода нет автора. Это код репозитория». Не вини автора. Сломалось — значит, пропустила система; чиним систему.

## 4. Защита (22 мин · слайды 29–38)

- **[29]** Заголовок раздела: «Never trust the contributor» — ни новичку, ни эксперту, ни агенту, ни себе. Дисциплина first.
- **[30]** «main всегда рабочий»: пять правил защиты ветки. Правило, которое можно обойти «один раз, срочно», правилом не является.
- **[31]** Диаграмма fail fast: формат → анализ → сборка → тесты → безопасность; «не отформатировано — не заслуживает тестирования».
- **[32]** Столбики «где дешевле поймать ошибку»: pre-commit hook, CI, review, пользователь. Pre-commit hook — удобство, CI — закон.
- **[33]** «Репозиторий без CI — свалка»: workflow GitHub Actions, собранный из actions, включая свои. Стройте CI из actions, а не из команд в yaml. Своя action логически завершена и обособлена.
- **[34]** Фраза: «Код без теста — это мнение. Код с тестом — факт». Эмоциональный блок: личная история о том, что сломалось без теста.
- **[35]** «Тесты: что вы обязаны требовать»: PR без теста, красный тест, баг → сначала тест, тест как документация, тест от ИИ.
- **[36]** «Review — это защита, а не формальность»: ИИ-ревьюер советует, человек решает. Последнее слово — за лидером проекта; о нём следующая лекция.
- **[37]** Итог лекции: «Механизм не должен зависеть от доверия к конкретному человеку».
- **[38]** «Задавайте вопросы».
