## 1. Лидер (22 мин · слайды 3–10)

- **[3]** Заголовок раздела: важнее любого утверждения — наличие лидера.
- **[4]** Вопрос в зал: «Вы делали проект командой. Кто принимал окончательное решение?» Запомнить ответ «тот, кто больше всех писал».
- **[5]** «Инструкция по саботажу, 1944 год»: пять приёмов из Simple Sabotage Field Manual. Написано для диверсантов — читается как протокол обычного совещания. Всё лечится человеком, который выслушал и сказал «делаем так». Документ прикладывается к лекции.
- **[6]** Фраза: «Самый плохой лидер лучше, чем его отсутствие». Команда хочет лидера; без него она тильтует. Не стесняйтесь принимать и отклонять, поощрять и наказывать.
- **[7]** «Сержант»: доклады (письменно) → лидер слушает → решение → все бегут в одну сторону. Лидер собирает разведку, слушает, потом говорит: всем спасибо, бежим туда. Неверное решение исправят следующим, отсутствие решения исправить нечем.
- **[8]** «Лидером не назначают»: боевой генерал против штабного. Единственный способ стать лидером проекта — стать его главным контрибьютором.
- **[9]** «Что лидер должен»: отвечать, держать дисциплину, расставаться, стоять, вдыхать жизнь. Успехи — команды, провалы — ваши. Тот, кто не работает, деморализует остальных. «Весь мир делает иначе» — не аргумент.
- **[10]** Итог раздела: «Решение всегда за лидером проекта».

## 2. Управление задачами (22 мин · слайды 11–18)

- **[11]** Заголовок раздела: смотрим с двух сторон — владелец с бюджетом и разработчик.
- **[12]** «След изменения»: issue #42 → ветка → pull request #43 → коммит в main → релиз 1.4.0. Про любую строку можно выяснить, кто просил, кто сделал и кто принял.
- **[13]** «Задача — маленькая»: что не так, что считается готовым, один результат, milestone. Вклад измеряется числом принятых микровкладов.
- **[14]** «Draft и пинг»: draft pull request против ping until death. Состояние работы видно в репозитории, а не выясняется в переписке.
- **[15]** «Вы платите за артефакт, а не за время»: цена за задачу против оплаты за время. Дайте цену — придут; не пришли — мало дали. Рабочего дня нет, есть результат.
- **[16]** «Одна задача, две стороны»: владелец репозитория и разработчик. Владельцу достаточно знать профиль и адрес для оплаты. Разработчик жадный — и это честный сигнал.
- **[17]** «Эксперт — это риск»: знание в голове против знания в репозитории. От эксперта избавляются тем, что его знание становится артефактом.
- **[18]** «Нанимайте агентов»: агент — такой же контрибьютор, правила те же.

## 3. Поставка (24 мин · слайды 19–27)

- **[19]** Заголовок раздела: код в main — ещё не продукт.
- **[20]** Trunk-based против GitFlow.
- **[21]** Номер версии 2.4.1 с подписями MAJOR, MINOR, PATCH. Номер версии — обещание тем, кто от вас зависит.
- **[22]** «Не обещайте лишнего»: класс `Greeter` с открытым, устаревшим и закрытым методом. Не декларируем наружу лишнего: задекларировал — обязан держать совместимость. Удаление — только через предупреждение.
- **[23]** «Релиз — это артефакт»: коммит → тег → сборка в CI → пакет и changelog → пользователь.
- **[24]** Feature flags: с флагом и без. Деплой — ещё не релиз. Флаг — долг.
- **[25]** Canary: 1 % → 10 % → 50 % → 100 %, стрелка назад при ухудшении метрик. Откат — обычная процедура.
- **[26]** «Из чего на самом деле собран продукт»: SBOM, сканирование, автообновления, закреплённые версии.
- **[27]** «Соедините пользователя с репозиторием»: ошибка → кнопка «сообщить» в продукте → issue → исправление в релизе.
