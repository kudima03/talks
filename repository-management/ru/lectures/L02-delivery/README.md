# Л2. Лидер, задачи, поставка — тезисы

**Длительность:** 80 минут
**Цель:** студент понимает, кто управляет репозиторием, как ставится и оплачивается работа и как
изменение доходит до пользователя.
**Полный текст лекции:** [L02-delivery.md](L02-delivery.md)
**Слайды:** [slides/L02-delivery-slides.tex](slides/L02-delivery-slides.tex) —
37 кадров, один на каждый `[СЛАЙД n — …]` в сценарии.

Вторая из двух лекций. Первая построила механизм; эта — про то, кто им управляет, кто делает
работу и как сделанное доходит до людей. Заметная часть — позиция автора, и это говорится вслух.

## Как читать

Число в начале тезиса — кадр, на котором он живёт: **[7]**. Прочерк **[—]** значит, что кадра
нет и тезис идёт голосом.

## Сквозные тезисы

- Код без теста — мнение, код с тестом — факт.
- Автоматика говорит «можно», ИИ — «похоже, можно». Сказать «сливаем» должен кто-то один.
- Плохой лидер лучше, чем его отсутствие. Решение всегда за лидером проекта.
- Лидером не назначают: им становится главный контрибьютор.
- Платят за артефакт, а не за время. Вклад — число принятых маленьких вкладов.
- Номер версии — обещание. Наружу — только необходимое.
- Системе всё равно, кто ошибся: человек или ИИ.
- Разработчик отличается от вайбкодера тем, что может отвечать за результат.

## 0. Где мы (2 мин · слайды 1–2)

- **[1]** Титул.
- **[2]** Три опоры Л1: чего нет в репозитории — того не было; main всегда рабочий; никому
  не доверяем.
- **[2]** Механизм ничего не решает сам. Кто говорит «сливаем», «не будем», «выпускаем»?
- **[—]** Предупредить: лекция спорная, многое — позиция автора. Спорьте.

## 1. Тесты и review (10 мин · слайды 3–6)

- **[3]** Формат и сборку машина проверяет сама. Тесты она может только запустить; написать
  и потребовать их должны люди.
- **[4]** Вопрос в зал: что важнее — код или тест? Большинство обычно за код. Ответ —
  на следующем кадре.
- **[5]** Тест — маленькая программа, которая проверяет большую. Пример: вызвать приветствие
  с именем Ann, сравнить с «Hello, Ann!».
- **[5]** Код без теста — мнение. Код с тестом — факт.
- **[—]** Ответ на вопрос: важнее тест. Код с тестами можно переписать; тесты по коду
  не восстановишь.
- **[—]** Личная история автора: что сломалось без теста и во что обошлось. Две-три минуты.
- **[—]** Тест — единственное, что говорит правду о коде через год.
- **[5]** PR без теста подозрителен: чем автор докажет, что работает?
- **[5]** Красный тест — слияние запрещено. Привычно красный тест хуже отсутствующего.
- **[5]** Нашли ошибку — сначала тест, который её воспроизводит, потом исправление.
- **[5]** Тест — документация: как код задуман к использованию.
- **[5]** Тест от ИИ проверяется как код: он может быть зелёным всегда.
- **[—]** Тесты позволяют менять код, а не бояться его.
- **[6]** Автоматика ловит формализуемое, остальное — тот, кто читает.
- **[—]** «Выглядит хорошо» через десять секунд на пятьсот строк — не review.
- **[6]** ИИ-ревьюер: сразу, каждый PR, не устаёт, типовые ошибки — советует. Человек: знает,
  зачем продукт, видит, что решение не туда, отвечает — решает.
- **[—]** Как читать чужой код: задача → тесты → код. Замечания по делу, под строкой.
- **[6]** Сказать «сливаем» должен кто-то один. Кто?

## 2. Лидер и иерархия (20 мин · слайды 7–14)

- **[7]** Важнее любого утверждения из обеих лекций — наличие лидера.
- **[8]** Вопрос в зал: двое в команде хотят сделать по-разному — кто ставит точку? Запомнить
  ответ «тот, кто больше всех делал».
- **[9]** Руководство по простому саботажу, УСС, 1944. Дать прочитать молча.
- **[9]** Только через официальные каналы; всё в комитет не меньше пяти человек; спорить
  о формулировках; возвращаться к принятым решениям; призывать к осторожности.
- **[9]** Написано для диверсантов. Не напоминает протокол совещания? Лечится одним: человеком,
  который выслушал и сказал «делаем так».
- **[10]** Плохой лидер лучше, чем его отсутствие. Плохое решение можно заменить,
  отсутствие решения — нет.
- **[—]** Команда хочет лидера; без него перестаёт хотеть работать. Не стесняйтесь принимать
  и отклонять.
- **[11]** Сержант: собрал разведку, выслушал, «всем спасибо, бежим туда». Слушает всех,
  решает один.
- **[11]** Лидер не обязан выиграть спор, чтобы принять решение. Неверное решение исправят
  следующим.
- **[11]** За неверный приказ сержанта расстреливают: решает один — отвечает один.
- **[11]** Доклады — письменно: через полгода спросят, почему решили так.
- **[—]** Пример: сорок комментариев под изменением на двадцать строк. С лидером — один
  комментарий: «прочитал обоих, делаем так».
- **[12]** Кто лидер? Единственный способ стать лидером — стать главным контрибьютором. Вернуться к ответу
  из зала.
- **[12]** Боевой генерал знает проект руками, ему верят. Штабной двигает карточки, его терпят.
- **[—]** Позиция автора; возражение «управление — отдельная профессия» выслушать.
- **[13]** Отвечать: успехи — команды, провалы — ваши.
- **[13]** Дисциплина: жёсткость к работе, а не к людям.
- **[13]** Расставаться: тот, кто не работает, деморализует остальных.
- **[13]** Стоять: «все так делают» — не аргумент; попросить предложение артефактом и решить.
- **[13]** Вдыхать жизнь: проект не бывает больше своего лидера.
- **[14]** Итог: review, спор, приоритет, выпуск — решение за лидером.

## 3. Управление задачами (20 мин · слайды 15–22)

- **[15]** Слушать с двух мест: владелец репозитория с бюджетом и разработчик.
- **[16]** След изменения: issue #42 → ветка → PR #43 → коммит в main → релиз 1.4.0. Каждое
  звено ссылается на предыдущее.
- **[16]** Про любую строку известно: кто просил, кто сделал, кто принял. PR без задачи
  подозрителен.
- **[17]** Задача маленькая: наблюдаемый факт, проверяемое условие готовности, один PR.
  Milestone — набор задач на выпуск.
- **[—]** Пример: «улучшить приветствие» против «без имени падает; должна печатать
  Hello, World! и завершаться с кодом ноль». Формулировать труднее, чем выполнять.
- **[17]** Вклад — число принятых маленьких вкладов, а не часы и не строки.
- **[18]** Draft PR — в первый день: видно, что работа идёт; ошибку направления ловят рано.
- **[18]** Ping until death: задача без ответа не лежит; молчание — не статус. Пинговать
  может бот.
- **[19]** Позиция автора: платить за артефакт, а не за время. Сказать, что индустрия в основном
  устроена иначе.
- **[19]** Цена названа заранее; принято — оплачено сразу; не берут — мало дали; рабочего дня
  нет, есть результат.
- **[19]** За время: оплачено присутствие, лень не видна, «делал, думал, анализировал».
- **[19]** Вооружены деньгами, защищены системой контроля качества. Без защиты платить
  за задачи нельзя.
- **[20]** Владелец: формулирует и оценивает, не верит на слово, знает профиль и куда платить,
  принимает или отклоняет.
- **[20]** Разработчик: выбирает сам, жадный, показывает результат, жалуется артефактом.
- **[20]** Никого не надо контролировать: всё спорное лежит в репозитории.
- **[—]** Студенту: открытый проект, задача для новичков, принятый PR. Десять таких говорят
  больше резюме.
- **[21]** Эксперт — риск: если что-то умеет один человек, проект принадлежит ему.
- **[21]** Эксперты берутся из устных объяснений. Избавляются не увольнением, а тем, что знание
  становится артефактом.
- **[22]** Агент — такой же участник: задача из репозитория, своя ветка, PR, те же проверки,
  доверия не больше.
- **[22]** Репозиторий, в который может войти человек с улицы, готов и к агенту.

## 4. Поставка (20 мин · слайды 23–29)

- **[23]** Код в main — ещё не продукт. Продукт — то, что дошло до пользователя.
- **[24]** Trunk-based: ветки живут часы и дни, конфликты маленькие и сразу, нужны сильные
  проверки. GitFlow: ветки на месяцы — нужен, когда поддерживают несколько версий сразу.
- **[—]** Пример: месяц в двух ветках, один переименовал функцию, второй вызывает её в тридцати
  местах. Долгая ветка — отложенный хаос.
- **[25]** 2.4.1: PATCH — исправили, MINOR — добавили, MAJOR — сломали совместимость.
- **[—]** Пример: 2.4.1 → 2.4.2 → 2.5.0 → 3.0.0.
- **[25]** Номер версии — обещание. Нарушили — версию зафиксируют навсегда.
- **[26]** Всё, что видно снаружи, обязаны поддерживать. По умолчанию закрыто.
- **[26]** `Greet` открыт — менять это MAJOR. `Format` закрыт — меняй когда угодно. `Hello`
  уходит через предупреждение.
- **[27]** Релиз — артефакт: коммит → тег → сборка в CI → пакет и описание изменений.
  С ноутбука не выпускают.
- **[27]** Описание изменений собирается из сообщений коммитов. По номеру версии получают
  точный исходный код.
- **[28]** Ваш код — меньшая часть продукта; остальное — поверхность атаки.
- **[28]** SBOM, сканирование, автообновления ботом, закреплённые версии — включая блоки
  в сценариях проверок.
- **[28]** Нашли уязвимость в популярной библиотеке: «она у нас есть?» SBOM отвечает за минуту.
- **[29]** Кнопка «сообщить об ошибке» в самом продукте → issue с версией, шагами и журналом.
- **[29]** Пользователь, который пожаловался, сделал вклад — как новичок из Л1. Круг замкнулся.

## 5. ИИ и вы (8 мин · слайды 30–37)

- **[30]** Навигатор ошибается. Что с этим делать?
- **[31]** Придумал зависимость → lock-файл, сканирование, review. Сломал совместимость →
  тесты, проверка API. Вечно зелёный тест → review теста. Забыл документацию → шаблон PR.
  Сделал не то → задача с проверяемым условием.
- **[31]** Пауза. Ни одна строка справа не про ИИ: это те же механизмы, что и для человека.
- **[32]** Вы — координатор людей и агентов и последняя точка контроля.
- **[32]** Интуиция разработчика появляется одним способом: пишете и читаете код сами.
- **[—]** Ответ на вопрос из Л1: разработчик может отвечать за результат. Вайбкодер едет
  в реку, потому что так показывал навигатор.
- **[33]** Порядок действий в хаосе: философия → организация → защита → задачи → поставка.
- **[34]** Источники. Не читать вслух.
- **[35]** Это был курс не про Git.
- **[36]** Контакты. Вопросы. Если их нет: с каким тезисом вы не согласны? Оформите возражение как issue.
- **[37]** Рекомендовано к прочтению: Code Ahead (Егор Бугаенко) — полуавтобиографический роман
