# Курс по .NET — структура

Спецкурс для 4-го курса БГУИР. **10 лекций × 80 минут**, лабораторные коррелируют с лекциями.

**Сквозная цель:** на выходе студент собирает WebAPI-сервис из частей, понимая каждую часть.

**Принципы построения:**

- внутри каждой темы движение от общего к деталям — каждая подтема сложнее предыдущей;
- .NET internals — только мельком, с целью направить на самостоятельное изучение;
- всё показываем через `dotnet` CLI;
- каждая лаба добавляет к сервису ровно один слой из прочитанной лекции.

## Решения по объёму

Исходных заметок хватает примерно на 12–13 лекций при 10 слотах. Темы не вырезаны, а понижены
в статусе до обзорного блока плюс лабораторной работы:

| Тема | Статус |
|---|---|
| .NET Aspire | 5 мин обзора в Л8 + используется в лабе 8 |
| OpenTelemetry | 5 мин в Л7 сразу после логирования |
| Quartz.NET | 5 мин в Л10; сам механизм фоновых сервисов — в Л5 |
| Глубокие фичи EF Core | сжаты в блок «правила и грабли» — это совпадает с тезисом «делайте просто, без лютых фокусов» |
| ADO.NET | 20 мин в Л9, дальше только в лабе |

Если нужен свободный слот — слить Л3 и Л4 в одну плотную лекцию по C# (при условии, что
курс уже знает синтаксис) и отдать освободившееся EF Core или безопасности.

## Добавлено сверх заметок

Без этого сервис не собрать:

- асинхронность как отдельный крупный блок (Л4);
- обработка ошибок и исключения как тема языка (Л4) и как единственное middleware (Л5);
- работа с файлами как наглядный пример владения unmanaged-ресурсом (Л4);
- OpenAPI и версионирование API (Л6).

Сознательно **не** входит в курс: ProblemDetails и прочие надстройки над ответом — фокус
на чистом WebAPI, ошибки формирует exception handling middleware.

## Не покрыто, стоит решить отдельно

- исходящие HTTP-вызовы: HttpClient, typed clients, resilience;
- деплой, контейнеризация, CI.

Любым из них можно заменить блок в Л8.
