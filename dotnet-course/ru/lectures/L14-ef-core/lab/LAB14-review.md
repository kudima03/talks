Служебный файл; студенту выдаётся [LAB14-task.md](LAB14-task.md). Рекомендации, а не регламент.

**Приёмка живая, минут на десять.** Файл migration и `dotnet ef migrations list`, `curl` на
`POST /orders` и `GET /orders/{number}` с SQL в log рядом, затем одна правка вживую (см. «Правки
вживую»). На что смотреть:

1. **Шаг 1.** В `Shop.Domain` нет ни одного пакета EF Core и ни одного атрибута; из изменений —
   только закрытый конструктор `Order`. Конфигурации — два класса в `Shop.Data/Configurations`,
   в `ShopDbContext` только `DbSet` и `ApplyConfigurationsFromAssembly`.
2. **Шаг 2.** `dotnet-ef` — local tool в `dotnet-tools.json`, а не глобальный. В коде сервиса нет
   `Migrate()`/`MigrateAsync()`/`EnsureCreated()`; SQL-скрипт тринадцатой не подключён в AppHost;
   папка `Migrations` в коммите, файл `Initial` не правлен руками.
3. **Шаг 3.** `EfOrderStore` зарегистрирован как scoped, `PgOrderStore` остался в репозитории, но
   не зарегистрирован; handlers не изменились — они знают только `IOrderStore`. Чтение — с
   `AsNoTracking`, `Include` одной коллекции. Студент показывает SQL в log, а не пересказывает.

## Эталон

Всё ниже — с эталонного решения на dotnet SDK 10.0.114, `dotnet-ef` 10.0.15, EF Core 10.0.15,
`Npgsql.EntityFrameworkCore.PostgreSQL` 10.0.3, `EFCore.NamingConventions` 10.0.1, PostgreSQL 17.
Эталон — `Shop.Domain`, `Shop.Data` и `Shop.Api` с `IOrderStore` и `NpgsqlDataSource` из
контейнера, окружение Development, порт 5090, база в контейнере Docker. **AppHost, token и cache

## Правки вживую

| Правка | Что будет |
|---|---|
| `AddSingleton<IOrderStore, EfOrderStore>()` | Сборка чистая; в Development сервис не стартует: `Cannot consume scoped service 'Shop.Data.ShopDbContext' from singleton 'Shop.Domain.IOrderStore'` (в эталоне `IOrderStore` лежит в `Shop.Domain`) |
| Убрать `UseSnakeCaseNamingConvention()` из `AddOrders()` | Любой запрос к заказам — `500`; в log SQL с `o."Number"`, `o."Customer_Email"` и `42703: column o.Number does not exist` |
| Убрать `AsNoTracking` из `FindAsync` | Ответ тот же, SQL тот же; вопрос на понимание — что теперь хранит context до конца запроса и зачем |
| Изменить сущность и не добавить migration | `dotnet ef migrations has-pending-model-changes --project Shop.Data` → `Changes have been made to the model since the last migration. Add a new migration.` |

Чего в задании нет, но можно спросить устно: N+1 при lazy loading (сто заказов — сто один
запрос), `ExecuteUpdateAsync` для массовой отмены, проекция в DTO вместо `Include` для списка,
`EnableRetryOnFailure`, отчёт на Dapper рядом с EF Core.

## Вопросы и короткие ответы

- **Почему конфигурация в `Shop.Data`, а не атрибутами?** *Домен не должен знать о хранении:
  с атрибутами `Shop.Domain` ссылался бы на пакет ORM. После шага 1 у него по-прежнему ни одного
  пакета; `Shop.Data` ссылается на домен, а не наоборот.*
- **Почему не `MigrateAsync` на старте?** *Два экземпляра стартуют одновременно и оба применяют
  migration: второй падает или удваивает перенос данных; сервису нужны права на схему. Migration —
  отдельный шаг поставки, до выкладки.*
- **Чем SQL отличается от написанного руками?** *Один запрос с `LEFT JOIN` вместо двух; колонки
  перечислены все, включая `id` и `order_number` позиций; `LIMIT 1` — от `FirstOrDefaultAsync`,
  подзапрос — чтобы `LIMIT` относился к заказу, а не к строкам соединения; `ORDER BY` — чтобы
  собрать позиции по заказам. Параметр — как в тринадцатой.*
- **Без `Include` (усложнённый)?** *Связь не загружена, а lazy loading не включён — коллекция
  пустая, `Total()` считает ноль. С lazy loading `GET /orders` дал бы запрос за заказами и по
  запросу на каждый заказ — N+1, и в коде этого не видно.*
- **Дополнительное: второй запуск скрипта?** *Ничего: каждая команда под проверкой таблицы
  истории. `Initial` уже применён на чьей-то базе — правка в нём туда не попадёт.*

**Частые ошибки:** атрибуты `[Table]`/`[Column]` на `Order`; `Shop.Domain` ссылается на EF Core;
конфигурация написана в `OnModelCreating`; `Database.Migrate()` в `Program.cs`; `dotnet-ef`
установлен глобально; пропущен пакет `Microsoft.EntityFrameworkCore.Relational` — `CS1705` о
разных версиях EF Core в `Shop.Api`; `Design` без `--version "10.*"` — пакет под .NET 11 не
ставится на `net10.0`; забыт `.IsRequired()` у связи —
`order_number` в migration `nullable: true`; `EfOrderStore` как singleton; `PgOrderStore` удалён.
