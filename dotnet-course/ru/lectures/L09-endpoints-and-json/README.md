# Л9. Эндпоинты, контракт и JSON — тезисы

Лекция про контракт — поверхность сервиса, которую видят снаружи. Раздел 1 — два способа описать эндпоинт:
минимальный API и контроллеры, и почему мы берём первый. Раздел 2 — путь от запроса к параметрам: маршрутизация,
привязка, разбор строки в тип и его ловушки, DTO вместо сущности. Раздел 3 — валидация: FluentValidation,
исключение в фильтре, ответ в middleware из Л8. Раздел 4 — JSON: сопоставление типов, полиморфизм, настройки,
конвертеры, генератор кода, стриминг. Раздел 5 — OpenAPI и обратная совместимость.

## Сквозные тезисы

- Обработчик — делегат; минимальный API показывает его целиком в одной сигнатуре.
- Статусы — в типе результата: их проверяет компилятор и читает генератор документа.
- Ограничение маршрута — выбор маршрута, а не валидация.
- Разбор строки в тип — место, где контракт встречается с реальностью: формат фиксируется в контракте.
- DTO фиксирует контракт API. Наружу уходит DTO и никогда сущность.
- Невалидный запрос — нарушение контракта: исключение до обработчика, ответ в одном middleware.
- Настройки сериализации задаются один раз на всё приложение. Контракт держите плоским.
- Документ выводится из кода. Добавлять можно, менять и удалять нельзя.

## 1. Два способа описать эндпоинт (18 мин · слайды 2–15)

- **[2]** Раздел: обработчик — это делегат.
- **[—]** В прошлый раз остановились на конце конвейера; сегодня — обработчик и контракт.
- **[3]** Вопрос: кто видел контроллеры? Много — это второй способ, и он старше.
- **[4]** Минимальный API: группа, ограничение в маршруте, зависимости параметрами, типизированный результат.
  Ни класса, ни атрибутов, ни наследования.
- **[—]** Минимальный API давно не упрощённый вариант: группы, фильтры, авторизация, документ; новое
  появляется здесь первым.
- **[5]** Группы вкладываются: `/api/v1` с `RequireAuthorization()` закрывает весь API, исключения —
  `AllowAnonymous()` на маршруте.
- **[6]** Источник параметра — по типу и имени: путь, контейнер, `RequestAborted`, тело как JSON.
- **[7]** `Results<Ok<OrderDto>, NotFound>`: статусы в сигнатуре. `TypedResults` — конкретные типы,
  `Results` — общий `IResult`. Объект без результата — 200 с JSON, строка — текст, `Task` — пустой 200.
- **[8]** Контроллер: `[ApiController]`, маршрут на классе, `ControllerBase`, зависимость через конструктор,
  атрибуты методов.
- **[9]** Соглашения: имя на `Controller`, публичный метод — обработчик, сложный тип — тело,
  `ActionResult<T>` — любые статусы, экземпляр на запрос.
- **[10]** Вопрос: откуда фреймворк узнал о контроллере? Рефлексия.
- **[11]** При старте: сборка → метаданные (Л2) → типы → фильтр → атрибуты → таблица маршрутов.
- **[12]** Цена: контроллеры находятся рефлексией, обрезка их выкинет, AOT не поддерживается, фильтры и
  активация на каждом запросе. Минимальный API — прямая ссылка, генератор кода, AOT. Делегат в переменной в
  цикле генератор не видит.
- **[—]** Делегаты кэшируются, но накладные расходы контроллеров измеримы (Л15); для обычного сервиса
  разница не решает.
- **[13]** Что берём: минимальный API — всё в одном месте, честность типов, AOT. Контроллеры не устарели:
  проект на них, их механизмы, команда.
- **[—]** Асинхронность обработчика — договор с сервером (Л6). Контроллер растёт до двух тысяч строк;
  обработчик-функция сопротивляется.
- **[14]** Обработчики по ресурсам: статический класс, метод расширения `MapOrders`, обработчики —
  статические методы по имени, метаданные цепочкой. Файл запуска читается как список.
- **[15]** Мысль раздела: обработчик — делегат; контроллеры — то же через соглашения и рефлексию.

## 2. От запроса к типам .NET (18 мин · слайды 16–30)

- **[16]** Раздел: три шага, и каждый может сломаться.
- **[17]** Маршрутизация → привязка → разбор строки в тип → параметры обработчика.
- **[18]** Шаблоны: литерал, параметр, ограничение, два ограничения, остаток пути, умолчание.
- **[19]** Ограничение — выбор маршрута: `/orders/abc` — 404 от маршрутизации. Приоритет: литерал →
  ограничение → параметр. Два равных шаблона — `AmbiguousMatchException` на запросе; анализатор
  предупредит при сборке, если видит оба рядом.
- **[—]** Свои ограничения — для формата адреса, не для данных. Нечисловой идентификатор: 404 или 400 —
  договориться в команде.
- **[20]** Регистр пути, косая черта в конце и имена параметров строки запроса не важны. Метод не тот —
  405 с `Allow`. `HEAD` на маршрут с `MapGet` — тоже 405.
- **[21]** Привязка: путь, контейнер, контекст, строка запроса, другое имя, заголовок, тело.
- **[22]** Источники: путь, строка запроса (`ids=1&ids=2` — массив), заголовок только с атрибутом, тело —
  один сложный тип, форма. Без `Content-Type: application/json` — 415. `[AsParameters]` — объект из
  параметров.
- **[23]** Свой тип в параметре: `Email` со статическим `TryParse`; формат проверен при привязке,
  `email=bad` — 400.
- **[24]** Вопрос: `decimal`, пришло `12,5`. Ответ — 125.
- **[25]** Разбор по инвариантной культуре, одинаково на любой машине: `12,5` → 125, `03/04/2026` → 4 марта,
  `99` → несуществующее значение перечисления, `paid` → 400, пустое `page=` → 400. Формат — в контракте.
- **[—]** Культура машины — в коде, который разбирает сам: явная инвариантная культура. Режим
  `InvariantGlobalization` в манифесте сборки — для API правильный выбор. Даты — ISO 8601 и пояс.
- **[—]** Ошибка разбора — 400 от фреймворка; в Development — `BadHttpRequestException`, и обработчик
  ошибок из Л8 без отдельной ветки отдаст 500. Та же ветка вернёт 413.
- **[26]** DTO ≠ сущность: сущность — как храним, DTO — что обещали; `ToDto()` на границе.
- **[27]** Вопрос: зачем два типа?
- **[28]** Зачем DTO: не отдать лишнее; зафиксировать контракт API; белый список на входе против
  избыточной привязки.
- **[29]** Несколько DTO на ресурс: ответ, строка списка, создание без `Id` и статуса; преобразование
  методом расширения руками. DTO — record в проекте контракта.
- **[30]** Мысль раздела: три шага, каждый может сломаться; наружу — DTO, никогда сущность.

## 3. Валидация (14 мин · слайды 31–38)

- **[31]** Раздел: невалидный запрос — исключение, ответ формирует middleware.
- **[—]** Проверка на границе — самый дешёвый момент: глубже — непонятное исключение или плохие данные в
  отчёте.
- **[32]** Три ступени: атрибуты (в .NET 10 — и в минимальном API, но ответ в чужом формате), свои
  правила, FluentValidation.
- **[—]** Атрибуты хороши для настроек приложения (Л10): объект маленький, проверка один раз на старте.
- **[33]** Валидатор: класс на DTO, правила цепочкой, `RuleForEach`, свой предикат через `Must`.
  Тестируется отдельно, в базу не ходит.
- **[—]** Сообщения — часть контракта: клиенту-программе — код, человеку — текст. Регистрация — одной
  строкой на сборку.
- **[34]** Вопрос: валидатор нашёл ошибки — что делает обработчик? Бросает.
- **[35]** Ошибка контракта — исключение, 422, до логики; ошибка сценария — значение внутри логики (Л4).
- **[36]** Фильтр конечной точки на группе: DTO среди аргументов, валидатор из контейнера, бросок. Ветки в
  middleware: `ValidationException` → 422, `BadHttpRequestException` → его статус.
- **[—]** Короче — валидатор в параметрах обработчика и бросок в первой строке; фильтр лучше: забыть нельзя.
- **[37]** Три места: правила — валидатор, проверка — фильтр, ответ — middleware. Настоящий 422 с полями
  в именах JSON.
- **[—]** Ограничение размера списков и строк — первым в цепочке. Проверка «в каждом обработчике» —
  пять одинаковых строк и одна забытая.
- **[38]** Граница: валидатор — запрос сам по себе (422), логика — относительно мира (409). Размер страницы —
  тоже валидация; валидация — не авторизация (Л11).
- **[—]** Двойная проверка в фильтре и сервисе разойдётся. Мысль раздела звучит голосом: обработчик про
  ошибки не знает.

## 4. JSON и сериализация (22 мин · слайды 39–52)

- **[39]** Раздел: JSON — строки и числа, всё остальное — договорённость.
- **[40]** Вопрос: как называется `CustomerEmail` в JSON? `customerEmail`.
- **[—]** Смотрите на сырой JSON; сообщение об ошибке чтения читайте целиком.
- **[41]** Сопоставление: camelCase, чтение без регистра, `null`, перечисление числом, ISO 8601, `decimal`
  числом, нет поля — умолчание. Веб-умолчания выставлены за вас.
- **[—]** Публичные свойства, поля не участвуют; record — через конструктор. `null` в необязательном по
  аннотации — попросите сериализатор уважать аннотации. Перечисления — строками, всегда. Интервал и GUID —
  стандартные строки.
- **[42]** Числа и деньги: больше 2^53 — строкой; `decimal` уходит числом, клиент читает `double`; деньги —
  строкой или в копейках. Числа из строк веб-умолчания читают.
- **[—]** Отсутствие и `null` неразличимы; `required` и обязательные параметры конструктора делают
  отсутствие ошибкой. Писать всё — ясность дороже десяти байт.
- **[43]** Вопрос: способ оплаты — как в JSON и обратно? JSON не несёт типов.
- **[44]** Полиморфизм: `[JsonPolymorphic]`, `[JsonDerivedType]`, дискриминатор `kind`.
- **[45]** Почему болит: дискриминатор не первый — 500; неизвестное значение — ошибка; менять нельзя;
  документ неидеален. Альтернативы — отдельные маршруты, поле-перечисление с условными правилами.
- **[46]** Настройки один раз: перечисления строками, конвертер, `RespectNullableAnnotations`,
  `RespectRequiredConstructorParameters`, отступы только в Development.
- **[—]** Для чужих контрактов (Л10) — свой набор настроек.
- **[47]** Свой конвертер: `Email` без него — объект с `value`, с ним — строка.
- **[48]** Генератор кода: `JsonSerializerContext`, атрибут на тип контракта, сначала контекст, потом
  рефлексия. Под AOT обязателен; в контексте — DTO.
- **[49]** Сериализация — слабое место платформы; кто напишет нормальный сериализатор — я первым перейду.
- **[—]** Претензии: порядок дискриминатора, `null` против отсутствия, сообщения, три слоя настроек,
  конструктор record. Newtonsoft был гибче, но медленнее и на рефлексии. Держите контракт простым.
- **[50]** Стриминг: `IAsyncEnumerable<OrderDto>` — массив по элементам, `Transfer-Encoding: chunked`,
  `[EnumeratorCancellation]`.
- **[51]** Цена: статус уходит с первым элементом; ошибка на третьем — 200, оборванный массив, `curl`
  выходит с кодом 18. Всё, что может упасть, — до первого элемента.
- **[—]** Server-Sent Events в .NET 10 — тот же принцип. Глубина вложенности и лимит тела — поднимать
  только для маршрута.
- **[52]** Мысль раздела: решения, принятые за вас, — один раз; контракт плоский.

## 5. Описание контракта наружу (8 мин · слайды 53–58)

- **[53]** Раздел: документ генерируется из кода.
- **[54]** OpenAPI: пути, параметры, ответы из типизированных результатов, схемы из DTO. `AddOpenApi`,
  `MapOpenApi`; у `GET /orders/{id}` — 200 и 404. Главный читатель — генератор клиентов.
- **[—]** Интерактивной страницы в шаблоне больше нет. Сравнение документов в конвейере сборки (Л15).
  Рукописная часть точна, пока её обновляют.
- **[55]** Вопрос: переименовали поле — сломались; добавили — нет.
- **[56]** Можно без версии: поле в ответ, необязательный параметр, маршрут, значение перечисления (если
  клиент переживает неизвестные). Нельзя: переименовать, тип, обязательность, смысл, формат.
- **[57]** Версия — в адресе, рядом со старой, устаревание в заголовках и документе, отключение в датах.
  Версия — это дорого: сначала спросите, нельзя ли добавить.
- **[58]** Мысль раздела: документ выводится из кода; контракт — обещание.
- **[—]** Дальше (Л10) — то, что «фреймворк подставит из контейнера»: DI, исходящие вызовы, конфигурация.

## Открытые вопросы

Авторское решение, не менять по умолчанию:

1. **Ветка `BadHttpRequestException` в `ErrorHandlingMiddleware` — новая для Л8.** В Development ошибка
   привязки (`page=`, `email=bad`, нечитаемое тело) бросает `BadHttpRequestException`, и middleware из Л8
   отдаёт 500; в Production фреймворк сам отвечает пустым 400. Проверено запуском. Сценарий Л9 добавляет ветку
   `bad.StatusCode` (кадр 36) и закрывает этим открытый вопрос 2 из Л8 (413 → 500); листинг кадра 24 в Л8 не
   менялся.
2. **`RespectRequiredConstructorParameters` меняет `CreateOrderDto`.** С настройкой отсутствующий
   `deliveryDate` без значения по умолчанию — ошибка чтения, поэтому в DTO `DateOnly? DeliveryDate = null`.
   Если настройку убрать из лабораторной, умолчание можно оставить.
3. **Латинский шрифт-замена (Latin Modern) не проверялся** для этой колоды; собиралась с PT Sans.
