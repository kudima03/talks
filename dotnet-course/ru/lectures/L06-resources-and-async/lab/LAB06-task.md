# Лабораторная 6. Журнал заказов: потоковый разбор большого файла

**К лекции:** [Л6. C#: ресурсы, файлы и асинхронность](../L06-resources-and-async.md)
**Условие:** проекты собираются и запускаются **из терминала**, как и раньше. Код пишется в
любом редакторе.
**Сдаётся вживую:** отчёта нет. Вы садитесь за терминал со своим проектом, показываете
результат и отвечаете на вопросы по любому шагу.

## Что нужно поставить заранее

Ничего нового: хватит .NET 10 SDK. Нужны оба проекта — `Shop.Domain` и `HelloWorld` из пятой
лабораторной. Для генератора входного файла нужны `bash` и `awk`: на Linux и macOS они уже есть,
на Windows — Git Bash или WSL, тот же терминал, в котором вы выполняли `echo $?` в четвёртой
лабораторной. Освободите на диске около полугигабайта: входной файл весит больше двухсот
мегабайт.

## Что должно быть готово

- У `HelloWorld` появился второй режим, **`digest`**: он разбирает журнал заказов на пять
  миллионов строк, считает число заказов и сумму по каждому статусу и выгружает отменённые
  заказы в отдельный файл. Оболочка из прошлых лабораторных работает как раньше, когда
  `HelloWorld` запущен без аргументов.
- Журнал читается **построчно и асинхронно**: `StreamReader` и `ReadLineAsync` с токеном
  отмены. Память программы не зависит от размера файла, и вы это измерили.
- Выгрузка пишется через **`await using`** и `WriteLineAsync`.
- **Таймаут** из аргумента командной строки: при отмене программа завершается сразу, выгрузка
  закрыта и заканчивается целой строкой.
- Программа **сама проверяет**, что после работы оба файла никто не держит, и печатает это.
- Сборка обоих проектов без единого предупреждения.
- Оба проекта под git; сгенерированные файлы — не в git.

## Что строим

| Тип или файл | Где | Что это |
|---|---|---|
| `gen-orders.sh` | `HelloWorld` | генератор журнала: строка `номер,почта,статус,сумма` |
| `OrderLine` | `HelloWorld` | одна строка журнала, разобранная через `TryParse` из `Shop.Domain` |
| `OrderLog.DigestAsync` | `HelloWorld` | потоковый разбор: журнал → итоги по статусам и выгрузка отменённых |
| `FileCheck.IsFree` | `HelloWorld` | проверка, что файл никто не держит открытым |
| режим `digest` | `HelloWorld` (`Program.cs`) | аргументы, таймаут, печать итогов |

Запуск:

```sh
dotnet run -- digest <журнал> <выгрузка> [секунды]
```

Секунды — сколько программе разрешено работать; без них — минута. Сессия может выглядеть так
(время и память у вас будут свои, числа итогов — те же: генератор выдаёт один и тот же файл на
любой машине):

```text

Paid: 1000000 orders, 498985000.00
Shipped: 1000000 orders, 499995000.00
Delivered: 1000000 orders, 501005000.00
Cancelled: 1000000 orders, 502015000.00
skipped: 50 lines
cancelled.csv: 1000000 lines
elapsed: 3.0 s
peak memory: 56 MB
orders.csv: free
cancelled.csv: free
$ dotnet run -- digest orders.csv cancelled.csv 1
cancelled after 1 s
```

Точный текст ответов — на ваше усмотрение. Важно, что в каждом случае понятно, что произошло.

## Шаги

Под каждым шагом — **«Вопрос»**: то, что вы должны уметь объяснить на приёмке. Вопросы
с пометкой **«усложнённый»** — со звёздочкой: их задают тем, у кого основной ответ уже есть.

### 1. Большой файл

1. Положите в папку `HelloWorld` генератор `gen-orders.sh`:

   ```sh
   #!/usr/bin/env bash
   # usage: ./gen-orders.sh [lines] > orders.csv
   awk -v n="${1:-5000000}" 'BEGIN {
       split("Created Paid Shipped Delivered Cancelled", status, " ")
       for (i = 1; i <= n; i++) {
           email = "customer" (i % 1000) "@example.com"
           if (i % 100000 == 0) {
               email = "broken-line"
           }
           printf "%d,%s,%s,%d.%02d\n", i, email, status[i % 5 + 1], i % 1000, i % 100
       }
   }'
   ```

   Каждая строка — один заказ: номер, почта, статус, сумма. Каждая стотысячная строка —
   испорченная: в ней почта без `@`.
2. Сделайте его исполняемым и запустите из папки `HelloWorld`:

   ```sh
   chmod +x gen-orders.sh
   ./gen-orders.sh > orders.csv
   ls -lh orders.csv
   head -3 orders.csv
   wc -l orders.csv
   ```

   Должно получиться около 223 мегабайт и ровно пять миллионов строк.
3. Добавьте в `.gitignore` строку `*.csv`: ни журнал, ни будущая выгрузка в репозиторий не
   попадают. Генератор — попадает.

**Вопрос:** вы будете запускать `dotnet run -- digest orders.csv ...` из папки `HelloWorld`.
Относительно чего программа ищет `orders.csv`? Что изменится, если запустить собранную сборку
из другой папки?

**Вопрос:** почему в git генератор, а не файл, который он делает?

### 2. Сначала — целиком

Прежде чем делать правильно, посмотрите, сколько стоит «просто прочитать файл». Этот код

   ```csharp
   Console.WriteLine($"chars: {text.Length}");

   ```

   `Process` живёт в `System.Diagnostics`. Время измерьте `Stopwatch` оттуда же.
2. Запустите на `orders.csv` и запишите три числа: символы, время, память.

### 3. Построчно

1. Напишите `OrderLine` — запись с номером, почтой, статусом и суммой — и статический
   `TryParse(string line, out OrderLine? order)`. Разбирайте строку так же, как разбирали команды
   в четвёртой лабораторной: части — паттерном списка, значения — через `Email.TryParse`,
   `Money.TryParse` и `Enum.TryParse` из `Shop.Domain`. Испорченная строка — это `false`, а не
   исключение.
2. Напишите `OrderLog.DigestAsync(string input, string output, CancellationToken ct)`. Пока без
   выгрузки: только чтение и итоги.
   - Откройте журнал через `using StreamReader`.
   - Читайте его в цикле `ReadLineAsync(ct)`, пока не вернётся `null`, как на кадре 52
     лекции.
   - Для каждой разобранной строки прибавляйте к итогу её статуса единицу и сумму. Итоги
     держите в словаре по статусу. Испорченные строки считайте отдельно.
   - Верните итоги вызывающему — запись или кортеж, на ваш выбор.
3. В `Program.cs` разберите аргументы `digest <журнал> <выгрузка> [секунды]` и вызовите
   `DigestAsync`. Пока передайте `CancellationToken.None` — настоящий токен появится на шаге 5.
   Без аргументов `HelloWorld` запускает оболочку, как раньше.
4. Напечатайте итоги по статусам, число испорченных строк, время и пиковую память — той же
   строкой, что на шаге 2. Сравните с шагом 2.

**Вопрос:** что лежит в памяти программы в каждый момент разбора? Почему пиковая память не
изменится, если файл станет в десять раз больше?

**Вопрос:** в пятой лабораторной такие итоги считал `GroupBy`. Почему здесь словарь, который

**Вопрос (усложнённый):** замените `ReadLineAsync(ct)` на `ReadLine()` и запустите. Скорее

### 5. Таймаут и отмена

1. В `Program.cs` создайте источник отмены с таймаутом из аргумента и освободите его, как любой
   ресурс:

   ```csharp
   using CancellationTokenSource cts = new CancellationTokenSource(TimeSpan.FromSeconds(seconds));
   ```

2. Передайте `cts.Token` в `DigestAsync`, а внутри — в каждый `ReadLineAsync`. В
   `WriteLineAsync` токен **не передавайте**: начатая запись строки должна закончиться, отмена
   срабатывает между строками, на чтении следующей.
3. Поймайте `OperationCanceledException` **в одном месте** — в `Program.cs`, вокруг вызова
   `DigestAsync`. Напечатайте, что разбор отменён, и завершите программу с кодом `2`, а не `0`.
   Внутри `DigestAsync` исключение отмены не ловите.
4. Запустите с таймаутом в одну секунду и проверьте:

   ```sh
   dotnet run -- digest orders.csv cancelled.csv 1
   echo $?
   wc -l cancelled.csv
   tail -n 1 cancelled.csv
   ```

   Программа должна закончиться примерно через секунду, а последняя строка выгрузки — быть
   целой строкой журнала.
5. Добавьте в `ERRORS.md` из четвёртой лабораторной строку про отмену: вид ошибки, как она
   выражена в коде, где обрабатывается, что видит человек.

**Вопрос:** кто бросил `OperationCanceledException` и как оно дошло до `Program.cs`? Кто по

**Вопрос:** зачем `using` у источника отмены? Что у него внутри такого, что надо освобождать?

**Вопрос:** на кадре 52 лекции токен передаётся и в `WriteLineAsync`. Почему здесь — нет? Где
тогда проходит граница, на которой программа может остановиться?

**Вопрос (усложнённый):** передайте токен и в `WriteLineAsync`, запустите с таймаутом раз

**Вопрос (усложнённый):** сейчас программу останавливает только таймаут. Нажмите Ctrl+C

### 6. Файл свободен

Главная проверка лабораторной: после работы программа не держит ни один файл. Проверять
нужно изнутри процесса — когда процесс завершился, операционная система закрывает все его
дескрипторы сама, и снаружи ошибку уже не увидеть.

1. Добавьте в `HelloWorld` проверку: открыть файл монопольно, без совместного доступа, и сразу
   закрыть. Не открылся — его кто-то держит.

   ```csharp
   public static class FileCheck
   {
       public static string IsFree(string path)
       {
           try
           {
               using FileStream probe = new FileStream(path, FileMode.Open, FileAccess.ReadWrite, FileShare.None);
               return $"{path}: free";
           }
           catch (IOException ex)
           {
               return $"{path}: BUSY ({ex.Message})";
           }
       }
   }
   ```

2. В режиме `digest` после разбора — и после удачного, и после отменённого — напечатайте
   `IsFree` для журнала и для выгрузки.
3. Сломайте: уберите у писателя `await using`, оставив обычное объявление переменной.
   Запустите без таймаута. Сравните три вещи: что напечатал `IsFree`, сколько строк программа
   сообщила записанными и сколько их на самом деле (`wc -l`), и чем кончается файл
   (`tail -c 60 cancelled.csv`).
4. Верните `await using`.

**Вопрос:** что напечатал `IsFree` у сломанной версии? Чей это «другой процесс»?

**Вопрос:** программа сообщила, что записала миллион строк. Куда делись те, которых нет в
файле, и почему последняя строка оборвана?

**Вопрос (усложнённый):** `IsFree` ловит `IOException`. Не противоречит ли это политике
ошибок из четвёртой лабораторной — ловить только то, что можете обработать, и в одном месте?
