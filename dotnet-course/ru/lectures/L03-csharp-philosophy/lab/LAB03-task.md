### 1. Создать библиотеку и подключить её

Рядом с папкой `HelloWorld` — не внутри неё:

```sh

```

`HelloWorld` в первой лабораторной:

```sh
cd ../Shop.Domain
git init
dotnet new gitignore
```

Откройте оба `csproj`.

лабораторной?

**Вопрос (усложнённый):** попробуйте провести ссылку в обратную сторону — из `Shop.Domain` на

### 2. Типы-значения с проверкой в конструкторе

Почта, деньги и идентификатор заказа — не строки и не числа, а свои типы. Образец — почта:

```csharp
namespace Shop.Domain;

public readonly record struct Email
{
    public string Value { get; }

    public Email(string value)
    {
        if (string.IsNullOrWhiteSpace(value) || !value.Contains('@'))
        {
            throw new ArgumentException($"Not an email: '{value}'", nameof(value));
        }

        Value = value;
    }

    public override string ToString() => Value;
}
```

По тому же образцу напишите сами:

- **`Money`** — сумма `decimal` и валюта. Валюта — не строка. Сложение двух сумм в разных
  валютах бросает исключение, отрицательная сумма не создаётся.
- **`OrderId`** — идентификатор заказа поверх `Guid` или `long`, на ваш выбор.

**Вопрос:** почему здесь `readonly record struct`, а не класс и не обычная `struct`? Где
в проекте проверяется формат почты — сколько таких мест?

**Вопрос:** почему в `Money` именно `decimal`? Сложите в `HelloWorld` тысячу раз по `0.1m`
и тысячу раз по `0.1` типа `double` и покажите оба результата.

**Вопрос (усложнённый):** создайте массив `new Email[2]` и посмотрите на `Value` его первого
элемента. Проверка в конструкторе есть, `Nullable` включён — откуда там `null` и почему
компилятор не предупредил?

### 3. Сущности и статус заказа

- **`Customer`** — покупатель: почта и имя.
- **`OrderItem`** — позиция заказа: товар, количество, цена за единицу.
- **`OrderStatus`** — перечисление: `Created`, `Paid`, `Shipped`, `Delivered`, `Cancelled`.
- **`Order`** — заказ: идентификатор, покупатель, позиции, статус. Статус снаружи **только
  читается**; меняет его **один** метод, который бросает исключение при недопустимом
  переходе. Допустимы: `Created → Paid`, `Created → Cancelled`, `Paid → Shipped`,
  `Paid → Cancelled`, `Shipped → Delivered`. Всё остальное — нет.

Какую ступень лестницы из лекции взять для каждого — `record` или класс — решаете вы.

**Вопрос:** что вы выбрали для `Customer`, `OrderItem` и `Order` и почему? Спросите у каждого
то, что спрашивали в лекции: это данные или поведение?

**Вопрос (усложнённый):** два заказа с одинаковым идентификатором, покупателем и позициями —
это один заказ или два? А два покупателя с одинаковыми почтой и именем? Как ваш выбор типа
отвечает на эти вопросы?

### 5. Доступ: всё закрыто, пока не решено иначе

Пройдите по всем типам `Shop.Domain` и оставьте `public` только то, что входит в контракт
библиотеки. Всё вспомогательное — например, таблицу допустимых переходов статуса — сделайте
`internal`. Классы, которые не проектировались как база, — `sealed`.

Попробуйте обратиться из `HelloWorld` к одному из `internal`-типов и соберите.

**Вопрос:** что сказал компилятор? Что означает `internal` — «внутри папки», «внутри
пространства имён» или что-то третье?

**Вопрос (усложнённый):** добавьте в `Shop.Domain.csproj`

```xml
<ItemGroup>

```

### 6. Проверить, что типы ведут себя как задумано

Напишите в `Program.cs` приложения `HelloWorld` проверки, каждая печатает свой результат:

- два одинаковых `Customer` равны по `==`;
- два заказа, собранные из одинаковых данных, **не** равны;
- `Email` работает ключом `Dictionary`: положили по одному экземпляру, нашли по другому,
  созданному из той же строки;
- `with` создаёт изменённую копию покупателя, оригинал не меняется;
- `ToString()` у `Customer` печатается читаемо;
- сложение денег в разных валютах, почта без `@` и недопустимый переход статуса бросают
  исключения — поймайте их и напечатайте сообщения.

**Вопрос:** почему `Customer` печатается как `Customer { Email = ..., Name = ... }`, хотя
`ToString` вы для него не писали? Что напечаталось бы на месте почты, если бы в `Email` не было
своего `ToString`?

**Вопрос (усложнённый):** почему `Email` работает ключом словаря без единой строки кода про
равенство и хэш? Что бы сломалось, если бы вы написали для типа-ключа `Equals`, а
`GetHashCode` забыли?
